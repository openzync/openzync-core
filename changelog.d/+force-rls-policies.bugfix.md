Enforce the row-level-security policies instead of only declaring them. The 19 tenant tables carried `org_isolation_*` policies, but PostgreSQL exempts the table *owner* from RLS and the application role owns every table, so all of them were inert — an org-scoped query returned every tenant's rows. Migration `0059` applies `FORCE ROW LEVEL SECURITY` to all 19 tables (no role split, no `DATABASE_URL` change), recreates every policy with a fail-closed tenant expression (`NULLIF(current_setting('app.org_id', true), '')::uuid` — an unset context now yields no rows instead of a 500), and adds two narrow policies for the public flows: a SELECT-only lookup of one organization by its join code and an INSERT-only policy for the brand-new organization row the signup path creates. The INSERT-only policy's CHECK is the same expression the SELECT policy uses (`id = NULLIF(current_setting('app.org_id', true), '')::uuid`), so a session may only insert the organization it is bound to — the previous unconditional `WITH CHECK (true)` was OR'ed over the `FOR ALL` policy and let a tenant-bound session insert an arbitrary organization row.

Five further tenant tables carried an `organization_id` but had **no** row-level security at all — no policy and `relrowsecurity = false`: `custom_instructions`, `episode_blobs`, `fact_invalidation_events`, `prompt_templates` and `webhook_endpoints` (the last one holds the per-endpoint webhook `signing_secret`). Migration `0059` now brings all five under the same org-isolation policy, so a cross-organization read of them returns no rows and a cross-organization write is refused by the database instead of relying on the application-layer ownership check. Because these five had never had RLS enabled, the migration applies `ENABLE ROW LEVEL SECURITY` before `FORCE` on them, and the downgrade drops their policy and disables RLS again to restore the pre-`0059` catalog state exactly.

The webhook endpoint lookup now binds the tenant to the session before it reads (`WebhookRepository.get_active_endpoints_for_event`) and the post-commit fact webhook effect initialises the context on its fresh session (`FactInvalidationService`), so an event can no longer be silently dropped because the session held a pooled connection with no tenant. The webhook `events` payload is also encoded as text: `orjson.dumps` returns bytes, which asyncpg rejects for a `VARCHAR` parameter, so creating or updating a webhook endpoint failed with a 500.

The tenant context is bound transaction-locally, so it is discarded by the end of the transaction and can never leak into the next request; `core.rls.RlsAsyncSession` re-binds it to the transaction that follows a mid-request commit, so the commit no longer leaves later statements un-tenanted. The public paths that only learn their tenant mid-request — signup, org-code join, login, refresh-token rotation, MFA and invite acceptance — bind the session to the resolved organization before their org-scoped writes.

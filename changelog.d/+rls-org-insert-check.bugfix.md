Close the over-wide `org_anon_insert` policy on `organizations`. The policy was `FOR INSERT WITH CHECK (true)`, and permissive policies are OR'ed — so the unconditional CHECK overrode the `FOR ALL` policy's `id = NULLIF(current_setting('app.org_id', true), '')::UUID` and a session bound to a normal tenant could insert an organization row for an arbitrary id. The ORM path was rejected only because SQLAlchemy appends a `RETURNING` clause, which the SELECT policy filters; a raw `INSERT` without `RETURNING` landed the row. The CHECK is now the same expression the SELECT policy uses, so a session may only insert the organization it is bound to. The signup path is unaffected: it mints the organization id in Python and binds the session to it *before* the flush, because PostgreSQL filters the `RETURNING` clause of an INSERT with the table's SELECT policy — a session that is not bound to the new organization cannot read the row back, and the insert is rejected with "new row violates row-level security policy" even when the INSERT's own CHECK passed.

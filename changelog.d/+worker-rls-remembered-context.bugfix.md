Bind the RLS tenant context on the worker tasks the way the rest of the code base does. Nine worker tasks (`cleanup_orphan_blobs`, `compute_observations`, `enrich_episode`, `expire_graph_edges`, `extract_blob_text`, `reconcile_enrichment`, `reconcile_graph_edges`, `reconcile_temporal`, `summarise_community`) set `app.org_id` / `app.bypass_rls` with a bare `set_config`, so the context was never remembered on the session: after the task's own commit the re-bind restored an *empty* context and the session silently ran un-tenanted — a fail-closed no-op that reported success. They now use `core.rls.set_tenant_context` / `core.rls.set_bypass_rls`, which the session remembers and re-applies after every commit and rollback, so a task that commits mid-flight stays bound to its tenant. The cross-org discovery scans keep the bypass only for the scan itself: the per-organization work drops it again and binds the tenant, so it runs tenant-scoped instead of unrestricted.

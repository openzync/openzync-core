Make the RLS tenant-context handling effective on the API request path. The context used to be bound with *session* scope (`set_config('app.org_id', …, false)`) so it would survive a mid-request `COMMIT`, but a session-scoped `SET` lives on the pooled CONNECTION: `Session.commit()` returns that connection to the pool and the session's next statement checks out a connection that may be carrying another tenant's context, so a tenant could survive on a connection the pool hands to the next request — and, worse, be observed by the request that committed it. The context is now bound **transaction-locally** (`set_config(…, is_local => true)`), so PostgreSQL discards it when the transaction ends and it can never be carried onto another request's connection; a statement that runs without a bound context matches no rows (fail-closed). `core.rls.RlsAsyncSession` re-binds the remembered context to the session's next transaction after every commit and rollback, so a mid-request commit no longer leaves the session un-tenanted. `dependencies.db.get_db` / `get_db_superadmin` release the context with `release_tenant_context`, which now only drops the remembered context and rolls the transaction back — there is no reset to commit, because there is nothing left standing on the connection. The reset helper lives in `core/rls.py` (`release_tenant_context`) — the scope semantics are in one place, shared by the API and the workers — and the worker call sites import it from there.

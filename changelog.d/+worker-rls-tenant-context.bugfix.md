Bind the RLS tenant context (`app.org_id`) on every worker DB session and release it before the connection returns to the pool. Under forced row-level security (migration 0059) an unbound session sees zero rows and cannot write, so the embedding, fact-embedding, user-summary, entity-linking, entity-merge, prompt-renderer, audit-log and worker-bootstrap paths were silently doing nothing. The context is bound transaction-locally, so it is discarded by the end of the transaction and cannot leak into the next task on the same pooled connection; `core.rls.RlsAsyncSession` re-binds it to the transaction that follows a commit. The worker's shared session factory now also initialises an empty tenant per session, so a task that forgets to bind one fails closed instead of reading another org's rows.

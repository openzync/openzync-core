Initialise the RLS tenant context in the two remaining session paths that did not, and document the invariant that keeps a foreign tenant away from a query. The tenant context is bound transaction-locally, so a session that never binds one matches no rows at all — the guarantee comes from every session initialising the context as its **first** statement (`init_context`) and from `core.rls.RlsAsyncSession` re-binding it to the transaction that follows every commit. Two paths broke that rule: the post-commit graph edge-sync effect opened a fresh `AsyncSession` on the request's engine and queried the RLS-protected graph tables with it, so a supersession expiry could silently match no rows; it now initialises the context with the tenant before the backend reads. The `write_audit_log` worker task bound the tenant only when an organisation was known and left the session uninitialised otherwise; it now always initialises the context. An organisation-less audit row belongs to no tenant, so the tightened `audit_logs` policy no longer admits it to a tenant-scoped session — the task writes it under an explicit RLS bypass instead. `core.rls` now states the invariant, the session-creation paths that satisfy it, and exactly how it breaks.

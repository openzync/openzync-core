## [1.0.0] - 2026-10-22

### Breaking Changes

- BREAKING: reject blob-refs-without-files with 422 and return 502 (not 500) when OpenBao is unreachable at worker startup. Also: exact-match auth public paths (closes prefix bypass), rate-limit off-by-one fix plus RATE_LIMIT_ENABLED kill-switch and trusted-proxy XFF handling, S3 null-byte filename sanitization with streaming upload, ID-only ARQ payloads with Redis dedupe, and 300 s presigned-URL cache. (+auth-ratelimit-blob-hardening)
- Require `current_password` to change the account email address — requests without it now fail with 422. (+email-change-current-password)
### Added

- Add `limit` (1–500) and `cursor` pagination to the classifications and structured-extraction list endpoints; `total` now reports the full collection size and responses carry `next_cursor` and `has_more`. Cursors are validated against the sort they were minted with and rejected when they no longer match. (+paginate-list-endpoints)
### Fixed

- Add `OZ_OLLAMA_EMBED_URL` to the admin system-setting categories, fixing a 500 raised by the missing-category lookup when listing system settings. (+admin-system-settings-categories)
- Reject an expired API key on the Redis cache-hit path — the cached entry now carries `expires_at` and is re-checked with the same comparison the database path uses, so a key can no longer authenticate for up to five minutes past its expiry. (+api-key-cache-expiry)
- Make the API key `last_used_at` write a single conditional UPDATE (only when the stored value is older than five minutes) instead of an unconditional write on every authenticated request. (+api-key-last-used-throttle)
- Make the RLS tenant-context handling effective on the API request path. The context used to be bound with *session* scope (`set_config('app.org_id', …, false)`) so it would survive a mid-request `COMMIT`, but a session-scoped `SET` lives on the pooled CONNECTION: `Session.commit()` returns that connection to the pool and the session's next statement checks out a connection that may be carrying another tenant's context, so a tenant could survive on a connection the pool hands to the next request — and, worse, be observed by the request that committed it. The context is now bound **transaction-locally** (`set_config(…, is_local => true)`), so PostgreSQL discards it when the transaction ends and it can never be carried onto another request's connection; a statement that runs without a bound context matches no rows (fail-closed). `core.rls.RlsAsyncSession` re-binds the remembered context to the session's next transaction after every commit and rollback, so a mid-request commit no longer leaves the session un-tenanted. `dependencies.db.get_db` / `get_db_superadmin` release the context with `release_tenant_context`, which now only drops the remembered context and rolls the transaction back — there is no reset to commit, because there is nothing left standing on the connection. The reset helper lives in `core/rls.py` (`release_tenant_context`) — the scope semantics are in one place, shared by the API and the workers — and the worker call sites import it from there. (+api-rls-tenant-context-reset)
- Stop trusting `X-Forwarded-For` for the client IP recorded in audit log entries — the direct peer address is used, so a spoofed header can no longer forge the logged source. (+audit-log-client-ip)
- Close a cross-tenant disclosure in the audit log. `AuditLogRepository.list` accepted an `organization_id` and never used it — the comment claimed "RLS handles org isolation", so the result set was whatever the policy admitted. The `org_isolation_audit_logs` policy admitted the rows with `organization_id IS NULL` to **every** tenant, and those rows are the platform-level trail of unauthenticated requests: the audit middleware enqueues one with `organization_id = None` for every request that carries no tenant, carrying the client IP, the user agent, the path, the query string and the request id. A session bound to one tenant could read 727 such rows on the dev database, including every `auth.login`, `auth.signup`, `auth.refresh` and `auth.verify_email` row of the whole platform — and `GET /v1/admin/audit-logs` is gated only by `members:read`, so any tenant admin saw the platform's authentication-attempt trail.

  The repository now applies the organization filter itself (`organization_id is not None` → `AuditLog.organization_id == organization_id`), so the tenant's result set is its own rows only. The policy is tightened to match: a NULL-organization row is no longer tenant-visible, and the write path for those rows — the ARQ audit task — runs under an explicit RLS bypass, because a row that belongs to no organization cannot be admitted by a tenant-scoped policy. The platform-wide view is unchanged: `organization_id=None` keeps meaning "whatever the caller's own isolation allows", and an RLS-bypass session still sees every row, the organization-less ones included. (+audit-log-tenant-filter)
- Decide audit response buffering before invoking the application, so GET, OPTIONS and exempt paths are no longer buffered in full and then discarded. (+audit-middleware-buffering)
- Fail closed with 503 when Redis is unreachable for the auth throttle and negative cache, instead of falling through to unthrottled Postgres on every request. (+auth-throttle-fail-closed)
- Propagate S3 delete failures from `delete_blobs` instead of logging and continuing, so database rows are never removed while their stored objects still exist. (+blob-delete-error-propagation)
- Let presigned download-URL generation raise `S3StorageError` instead of returning `None`, so a storage outage surfaces as an error rather than a successful response with a null URL. (+blob-download-url-loud-failure)
- Propagate blob text-extraction failures to the ARQ retry loop instead of recording them as successful extractions — unsupported MIME types remain an explicit no-text outcome without the done bit set. (+blob-extraction-failure-retry)
- Fix periodic observation scans aborting entirely when the FalkorDB co-occurrence query timed out: the query now carries a server-side timeout and a result cap, and a co-occurrence backend failure is fail-open (logged, counted as zero) so temporal and behavioral detection still run. One slow graph query no longer blocks the whole non-blocking scan. (+co-occurrence-query-timeout-fail-open)
- Fix the context export cache serving a cached `format=json` payload in response to a `format=text` request by scoping the cache key to `format` and `limit`. (+context-export-cache-key)
- Size the SQLAlchemy connection pool from settings (`OZ_DB_POOL_SIZE` / `OZ_DB_MAX_OVERFLOW`, default 5 + 1) in both the API and the worker, so `replicas x (pool_size + max_overflow)` stays inside the database's `max_connections` budget at HPA scale. (+db-pool-sizing)
- Assign `sequence_number` as `start_seq + i` from a server-computed base in batch episode inserts, removing the in-batch-index fallback that restarted numbering at 0 on every batch. (+episode-sequence-start-seq)
- Raise the FastAPI floor to `>=0.117.0` and remove the permanent `fastapi.routing.is_body_allowed_for_status_code` monkey-patch — FastAPI 0.117.0 (fastapi/fastapi#9425) resolves a `-> None` return annotation to `None` instead of `type(None)`, so 204 routes no longer need the patched assertion. (+fastapi-monkey-patch-removal)
- Enforce the row-level-security policies instead of only declaring them. The 19 tenant tables carried `org_isolation_*` policies, but PostgreSQL exempts the table *owner* from RLS and the application role owns every table, so all of them were inert — an org-scoped query returned every tenant's rows. Migration `0059` applies `FORCE ROW LEVEL SECURITY` to all 19 tables (no role split, no `DATABASE_URL` change), recreates every policy with a fail-closed tenant expression (`NULLIF(current_setting('app.org_id', true), '')::uuid` — an unset context now yields no rows instead of a 500), and adds two narrow policies for the public flows: a SELECT-only lookup of one organization by its join code and an INSERT-only policy for the brand-new organization row the signup path creates. The INSERT-only policy's CHECK is the same expression the SELECT policy uses (`id = NULLIF(current_setting('app.org_id', true), '')::uuid`), so a session may only insert the organization it is bound to — the previous unconditional `WITH CHECK (true)` was OR'ed over the `FOR ALL` policy and let a tenant-bound session insert an arbitrary organization row.

  Five further tenant tables carried an `organization_id` but had **no** row-level security at all — no policy and `relrowsecurity = false`: `custom_instructions`, `episode_blobs`, `fact_invalidation_events`, `prompt_templates` and `webhook_endpoints` (the last one holds the per-endpoint webhook `signing_secret`). Migration `0059` now brings all five under the same org-isolation policy, so a cross-organization read of them returns no rows and a cross-organization write is refused by the database instead of relying on the application-layer ownership check. Because these five had never had RLS enabled, the migration applies `ENABLE ROW LEVEL SECURITY` before `FORCE` on them, and the downgrade drops their policy and disables RLS again to restore the pre-`0059` catalog state exactly.

  The webhook endpoint lookup now binds the tenant to the session before it reads (`WebhookRepository.get_active_endpoints_for_event`) and the post-commit fact webhook effect initialises the context on its fresh session (`FactInvalidationService`), so an event can no longer be silently dropped because the session held a pooled connection with no tenant. The webhook `events` payload is also encoded as text: `orjson.dumps` returns bytes, which asyncpg rejects for a `VARCHAR` parameter, so creating or updating a webhook endpoint failed with a 500.

  The tenant context is bound transaction-locally, so it is discarded by the end of the transaction and can never leak into the next request; `core.rls.RlsAsyncSession` re-binds it to the transaction that follows a mid-request commit, so the commit no longer leaves later statements un-tenanted. The public paths that only learn their tenant mid-request — signup, org-code join, login, refresh-token rotation, MFA and invite acceptance — bind the session to the resolved organization before their org-scoped writes. (+force-rls-policies)
- Match the Grafana overview dashboard's queue-depth PromQL selectors to the label the worker actually emits — the fully qualified queue name (`OpenZync:{env}:queue:{high|low}`) instead of the bare `high`/`low`, which matched no series and left the Grafana queue-depth panels permanently empty. A checked-in dashboard does not know the deployment environment, so the selector uses an anchored regex (`queue_name=~"OpenZync:.*:queue:high"`) that matches the qualified name in any environment. (+grafana-dashboard-queue-depth-label)
- Release the content-hash idempotency claim when an ingest fails, so a retry is no longer rejected as a duplicate of a write that never completed. (+idempotency-claim-release)
- Serialize Pydantic validation error details to plain strings before returning 422 from memory ingest, fixing `ValueError`-from-validator failures surfacing as plain-text 500s. (+ingest-validation-error-shape)
- Read upload byte streams per episode rather than re-reading a one-shot `UploadFile`, which returned empty content and silently ingested nothing for episodes sharing a file. (+memory-ingest-upload-stream)
- Match the admin dashboard's queue-depth PromQL selector to the label the worker actually emits — the fully qualified queue name (`OpenZync:{env}:queue:{high|low}`) instead of the bare `high`/`low`, which matched no series and left queue depth permanently empty on the dashboard. (+metrics-queue-depth-label)
- Delete stored S3 objects when wiping a project, so a wipe no longer leaves orphaned blob data behind. (+project-wipe-blob-removal)
- Fix episode enrichment failing on every run with a `DetachedInstanceError`: the prompt-template text was read after its database session had closed and rolled back. The template text is now fetched as a scalar inside the session, and recent session history is loaded the same column-only way, so enrichment no longer touches expired ORM state. (+prompt-template-detached-read)
- Record the real client IP behind a reverse proxy — uvicorn now runs with `--proxy-headers` and an explicit `--forwarded-allow-ips` (`OZ_TRUSTED_PROXY_IPS`, default `127.0.0.1`), so the per-IP rate limiters and the audit log are keyed on the client instead of the proxy instead of sharing one platform-wide bucket. (+proxy-aware-client-ip)
- Fix the sliding-window rate limiter under-counting requests that arrive in the same millisecond by giving each sorted-set member a unique suffix. (+rate-limit-window-accounting)
- Initialise the RLS tenant context in the two remaining session paths that did not, and document the invariant that keeps a foreign tenant away from a query. The tenant context is bound transaction-locally, so a session that never binds one matches no rows at all — the guarantee comes from every session initialising the context as its **first** statement (`init_context`) and from `core.rls.RlsAsyncSession` re-binding it to the transaction that follows every commit. Two paths broke that rule: the post-commit graph edge-sync effect opened a fresh `AsyncSession` on the request's engine and queried the RLS-protected graph tables with it, so a supersession expiry could silently match no rows; it now initialises the context with the tenant before the backend reads. The `write_audit_log` worker task bound the tenant only when an organisation was known and left the session uninitialised otherwise; it now always initialises the context. An organisation-less audit row belongs to no tenant, so the tightened `audit_logs` policy no longer admits it to a tenant-scoped session — the task writes it under an explicit RLS bypass instead. `core.rls` now states the invariant, the session-creation paths that satisfy it, and exactly how it breaks. (+rls-context-init-invariant)
- Close the over-wide `org_anon_insert` policy on `organizations`. The policy was `FOR INSERT WITH CHECK (true)`, and permissive policies are OR'ed — so the unconditional CHECK overrode the `FOR ALL` policy's `id = NULLIF(current_setting('app.org_id', true), '')::UUID` and a session bound to a normal tenant could insert an organization row for an arbitrary id. The ORM path was rejected only because SQLAlchemy appends a `RETURNING` clause, which the SELECT policy filters; a raw `INSERT` without `RETURNING` landed the row. The CHECK is now the same expression the SELECT policy uses, so a session may only insert the organization it is bound to. The signup path is unaffected: it mints the organization id in Python and binds the session to it *before* the flush, because PostgreSQL filters the `RETURNING` clause of an INSERT with the table's SELECT policy — a session that is not bound to the new organization cannot read the row back, and the insert is rejected with "new row violates row-level security policy" even when the INSERT's own CHECK passed. (+rls-org-insert-check)
- Fix a cross-tenant data leak in the RLS tenant context: the tenant is now bound **transaction-locally**, so it can never be carried onto a pooled connection that another request uses.

  `app.org_id` was bound with *session* scope (`set_config('app.org_id', :o, false)`), which means the value lives on the pooled CONNECTION. `Session.commit()` returns that connection to the pool, and the session's next statement checks out a connection that may be carrying a *different* tenant's context — nothing re-bound the tenant after the commit. Reproduced with a single-connection pool and two interleaved requests: request A (the platform organization) resumed with request B's tenant and read 10 422 episodes belonging to another organization. The RLS policies were working correctly; the tenant context itself was wrong. The leak was introduced by making RLS real (migration `0059`) — before that, RLS was inert and the application-layer organization filters were the only protection, and they were correct.

  The context is now bound with `set_config(..., is_local => true)` (`SET LOCAL`), so PostgreSQL discards it when the transaction ends. A statement that runs without a bound context matches **no rows** — the policy expression `NULLIF(current_setting('app.org_id', true), '')::UUID` is NULL and `organization_id = NULL` is never true — so a lost context is fail-closed by construction instead of widening a result set. The price of transaction-local scope is that a mid-request `COMMIT` discards the context; `core.rls.RlsAsyncSession` pays that price automatically by remembering the context on the session and re-applying it to the session's next transaction whenever the current one ends (commit **or** rollback). The re-bind statement is the first statement of the new transaction, so no statement of that transaction can observe a foreign tenant, on whichever connection the pool hands out.

  `core.rls` now documents the new scope and its fail-closed property, `core.rls.release_tenant_context` no longer has to reset a pooled connection (there is nothing left to reset — the transaction end discards the context), and the bypass (`app.bypass_rls`) and the join-code lookup (`app.lookup_code`) are transaction-local as well, so neither can outlive its transaction. (+rls-transaction-local-tenant-context)
- Fail loudly when an org's blob storage config cannot be read — a storage misconfiguration now raises `ExternalServiceError` (502) instead of silently writing the documents to the shared dev bucket, and the resolution reuses the app-level OpenBao and Redis clients instead of opening a new AppRole session per call. (+storage-config-fail-loud)
- Re-raise usage metering failures after logging instead of swallowing them, so a metering outage reaches the ARQ retry loop rather than silently dropping usage rows. (+usage-sink-failure-visibility)
- Fix worker-process fact invalidation crashing with `RuntimeError: ARQ pool has not been initialised`: the worker never initialised the shared ARQ pool (only the API lifespan did). The worker now initialises it at startup and closes it on shutdown; enqueue-failure semantics are unchanged — a failed expiry enqueue still raises loudly. (+worker-arq-pool-init)
- Probe workers over HTTP (`/health` for liveness, `/ready` for readiness) on the worker health port instead of an exec Redis ping, which only proved Redis was reachable. Also corrects the worker Dockerfile comment to the real default health port, 8081. (+worker-health-probes)
- Raise `GraphBackendUnavailableError` when worker org-config resolution fails instead of running enrichment under wrong defaults with a `None` config. (+worker-org-config-fail-loud)
- Bind the RLS tenant context on the worker tasks the way the rest of the code base does. Nine worker tasks (`cleanup_orphan_blobs`, `compute_observations`, `enrich_episode`, `expire_graph_edges`, `extract_blob_text`, `reconcile_enrichment`, `reconcile_graph_edges`, `reconcile_temporal`, `summarise_community`) set `app.org_id` / `app.bypass_rls` with a bare `set_config`, so the context was never remembered on the session: after the task's own commit the re-bind restored an *empty* context and the session silently ran un-tenanted — a fail-closed no-op that reported success. They now use `core.rls.set_tenant_context` / `core.rls.set_bypass_rls`, which the session remembers and re-applies after every commit and rollback, so a task that commits mid-flight stays bound to its tenant. The cross-org discovery scans keep the bypass only for the scan itself: the per-organization work drops it again and binds the tenant, so it runs tenant-scoped instead of unrestricted. (+worker-rls-remembered-context)
- Bind the RLS tenant context (`app.org_id`) on every worker DB session and release it before the connection returns to the pool. Under forced row-level security (migration 0059) an unbound session sees zero rows and cannot write, so the embedding, fact-embedding, user-summary, entity-linking, entity-merge, prompt-renderer, audit-log and worker-bootstrap paths were silently doing nothing. The context is bound transaction-locally, so it is discarded by the end of the transaction and cannot leak into the next task on the same pooled connection; `core.rls.RlsAsyncSession` re-binds it to the transaction that follows a commit. The worker's shared session factory now also initialises an empty tenant per session, so a task that forgets to bind one fails closed instead of reading another org's rows. (+worker-rls-tenant-context)
- Remove the worker's custom SIGTERM/SIGINT handlers and let ARQ own signal handling, restoring graceful shutdown and in-flight job draining. (+worker-signal-handling)
### Changed

- Sanitize client-supplied blob file names to an inert basename (path separators, parent refs and control characters stripped, 255-char cap); blank names are rejected with 422. (+blob-filename-sanitization)
- Honor the `cursor` query parameter on `GET /v1/observations` — a cursor from a previous response now returns the following page instead of the first. `total` reports the number of rows in the current page (the graph backend exposes no collection total) and responses include `next_cursor` and `has_more`. - Move `get_queue_name` out of the worker package. The queue-name builder lived in `services/worker/worker_settings.py` but was imported by API-side modules (`services/metrics_service.py`, `services/user_summary_service.py`, `services/memory_service.py`, `services/fact_service.py`, `services/webhook_service.py`, `services/graph_edge_sync_service.py`, `middleware/audit.py`) — the API reaching into the worker package for a label both sides share. It now lives in `core/queue_names.py` and every importer was updated. The label format (`OpenZync:{env}:queue:{high|low}`) is unchanged, so the metrics queries and the Grafana dashboard regex keep matching. (+queue-name-core-module)
- Set Redis to `noeviction` with AOF persistence enabled — DB 0 holds ARQ job and dedup keys alongside cache entries, so LRU eviction could silently drop queued work. (+redis-noeviction-aof)

## [1.0.0rc3] - 2026-09-30

### Breaking Changes

- Freeze embeddings to the canonical model `nomic-ai/nomic-embed-text-v1.5` (768 dims): migration 0054 converts `episodes`/`facts` embeddings to native `VECTOR(768)` with HNSW cosine indexes (non-conforming rows are nulled for re-embed), and per-org `embedding_model`/`embedding_dim` overrides are now rejected with 400 `embedding_frozen`. Ollama `nomic-embed-text` remains as the dim-compatible dev fallback. (+embedding-freeze)
- **BREAKING:** `DELETE /v1/projects/{project_id}/memory` now requires a JSON body `{"confirm": "<project_id>"}` matching the path project — a missing or mismatched confirm is rejected with 422 and nothing is deleted. A successful wipe is recorded as a destructive-action `memory.wipe` audit log entry carrying the actor, project ID, confirm-matched flag, timestamp, and deletion counts. (+p0-memory-delete-confirm)
- Message/episode listing now uses the v1 cursor envelope: legacy or malformed cursors are rejected with 400 `cursor_expired` (restart from page 1), and `get_by_project_id` ordering is aligned to `(sequence_number, id)` to match the keyset predicate.
  PII redaction is now fail-closed: an OpenBao/redaction outage returns 503 `pii_unavailable` with `Retry-After: 30` instead of persisting unredacted content.
  The legacy `quotas -> pii` config fallback is removed — orgs still carrying quota-stored PII config must migrate to the dedicated PII store before upgrading. (+p0-pagination-pii)
### Fixed

- Fixed API crash-loop on boot: the pgvector codec hook in `core/db.py` drove `register_vector` through the adapted connection's `await_` method, which SQLAlchemy 2.1 removed, while the unpinned `.[llm]` Docker install floated to 2.1.x — so every pooled connection raised `AttributeError` during lifespan startup and uvicorn exited. The hook now uses the documented `sqlalchemy.util.concurrency.await_only` bridge (identical behavior on 2.0.x, where the dialect's own `await_` is that same function), and both Docker images now build with a constraints file pinning SQLAlchemy/asyncpg/pgvector to the CI-tested versions (2.0.50/0.31/0.4.2), so a rebuild can no longer float past what the code is verified against, plus `numpy==2.2.6` (last release before the x86-64-v2 baseline wheels that cannot load on the production CPU).
- Fixed `/health` version reporting going stale at the hatch-vcs fallback: Docker builds and the CD pipeline now inject the release tag via the `APP_VERSION`/`OPENZYNC_VERSION` build-arg, which `core/_version.py` prefers over the packaged metadata. This was needed because the Docker build context ships without git history, so hatch-vcs could never resolve the tag and every image reported the fallback. Deployed environments now return the actually-released version, so the dashboard sidebar footer matches the running release instead of a frozen `1.0.0rc1`. (+app-version-build-arg)
- Fixed community detection running on stale state and crashing on real backend data: prior-run `community` nodes and `MEMBER_OF` edges are now excluded from the Label Propagation input (keyed on the cross-backend `type` contract) and prior communities are deleted before fresh ones are stored, so reruns replace instead of duplicating; the summarisation prompt reads `type` instead of `relationship_type` (which raised `KeyError` on every real edge); and `GET /graph/communities` `member_count` is computed at read time from `MEMBER_OF` edges instead of a stored attribute. Note: SurrealDB `delete_entity` removes only the node record, so incident `member_of` edge rows may survive a rerun cleanup as orphans — excluded from detection input regardless. (+community-detection)
- Fixed enrichment progress stalling at 41%: episodes in archived projects are now excluded from the progress counts (the workers never enrich them, so they sat as a permanent phantom backlog of ~3089). The dashboard percentage now runs 0–100% over enrichable episodes only, with new `archived_episodes`/`enrichable_total` fields on the summary so the excluded volume stays visible. (+enrichment-archived-progress)
- Fixed episodes wedged in the enrichment queue forever when extraction finds nothing: empty structured output and empty/filtered/deduplicated fact output now stamp their completion bit (assessed, nothing to store) instead of leaving the episode permanently pending, so the queue drains. (+enrichment-assessed-empty)
- Fixed FalkorDB `create_relationship` cloning endpoint nodes: the edge-pattern `MERGE` created bare duplicate `:Entity` nodes (id only, no name/type) and attached new edges to the duplicates instead of the real entities. Endpoints are now `MATCH`ed first and only the edge is merged; a missing endpoint raises `NotFoundError` instead of silently ghosting. (+falkordb-ghost-nodes)
- Fix FalkorDB v4 dialect (`<>` comparisons, v4 index DDL, loud schema bootstrap with a versioned re-run guard) and fail fast with a named error when OpenAI/Azure/OpenAI-like chat returns no choices instead of indexing into an empty list. (+falkordb-llm-hardening)
- Fixed session-scoped graph returning empty: `GET /graph/nodes?session_id=` traversed `:Session` stub nodes that are never created, so it always yielded `[]` (and the session graph page showed 0 nodes/0 edges). Added `GraphBackend.get_entities_for_episodes`; `GraphService` now resolves the session's episode IDs from PostgreSQL and filters `MENTIONS` edges by episode (capped, newest first). Existing graphs light up with no backfill; response shapes unchanged. (+session-graph)
- Fixed message/episode cursor keyset predicate to use tuple comparison on `(sequence_number, id)`, eliminating duplicate/skipped rows at page boundaries.
  Episode `sequence_number` is now server-assigned and contiguous via session `FOR UPDATE` + `MAX+1`, guarded by a partial unique index and backfill migration 0053 (duplicate sequence numbers eliminated; conflicts surface as 409 for client retry).
  Blob extraction failures are now fail-closed (raise + ARQ retry, success bit unset) instead of being marked successful.
  Content dedup is atomic via a Lua GET-or-SET claim: concurrent identical ingests replay the winner `job_id` and write a single row. (+p0-ingest-correctness)
### Changed

- Decoupled the FalkorDB/SurrealDB graph path from the PostgreSQL `graph_entities` stub table (never written by those backends). Migration 0056 drops the `facts` subject/object and `graph_observations` subject/related foreign keys to `graph_entities` (UUID columns kept; downgrade is not clean once orphan UUIDs accumulate). Admin stats/metrics entity counts, enrichment prompt user-entities, and the new `GraphBackend.get_entities_for_user` now read from the configured graph backend instead of the stub table — no API contract changes. FalkorDB/SurrealDB schema bootstrap is idempotent across duplicate-DEFINE variants (`already exists` / `already indexed`). (+graph-decouple)
- Changed the periodic enrichment reconciliation scan to match only episodes missing assessed LLM work and to skip soft-deleted rows, so it re-enqueues genuinely stale episodes instead of churning on rows that can never complete. (+reconcile-scan-mask)
